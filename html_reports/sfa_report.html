Selective Forwarding Attack (Gray-Hole)

Byzantine routing attack: compromised peers remain fully connected and pass all liveness checks, but silently discard every query routed through them.

Overview

Target: MockRAGNetwork (20-peer Barabási–Albert graph) or the real 3-node drag_data_source Docker deployment, routed via TTL-bounded BFS.

A subset of peers are monkey-patched to always return a silent miss on .query(). The paired defense (SelectiveForwardingDefense) tracks each peer's EMA response rate, blacklists collapsing peers, and gives the router a small bounded number of redundant-probe retries. Full technical writeup: reports/SFA_Security_Analysis_Report.md.

Why hit_rate stayed at 1.0 with a compromised peer

With only 3 real peers and a hop budget of query_ttl=3, the BFS router had enough redundancy to route around the single dropping peer on every one of 200 queries — a small-topology effect, not evidence the attack is ineffective in general (see the mock sweep above for how it degrades at larger scale / tighter hop budgets).

A previous run with --min_request_interval_s 0.1 was discarded

0.1s between requests is up to 600 requests/min against a server capped at 60/min per IP — it immediately triggered heavy HTTP 429 rate-limiting on source_0, which the SFA module already tracks explicitly (rate_limited_total) precisely because of this failure mode (§12.9 of the report). Re-run with the documented-safe 1.1s interval instead.

The random-strategy attacker never dents hit_rate on this 3-peer live topology (BFS redundancy absorbs it); the targeted high_connectivity attacker does (0.600), and the defense fully recovers it (1.000) by blacklisting exactly the one compromised peer and using 13 redundant-probe bypasses to get real answers anyway.

Key findings

  • Stealthy attacks are the real threat, not black-holes. A peer dropping only 10–30% of queries is far harder to detect than a full black-hole — the default threshold-based detector catches 0 of 2 such attackers across every tested seed; the statistically-principled binomial mode closes most of that gap but with a measured, non-zero false-positive cost.
  • Topology matters enormously. The same attack that's nearly invisible on a 3-node live deployment (hit_rate stays 1.0) collapses hit_rate to 0.54 on a 20-node mock network at 50% high-connectivity compromise — scale and hop-budget tightness are what expose the vulnerability.
  • All figures are single-trial, single-seed (per the report's own Fix Status Matrix) — real and reproducible, not yet statistically robust.
