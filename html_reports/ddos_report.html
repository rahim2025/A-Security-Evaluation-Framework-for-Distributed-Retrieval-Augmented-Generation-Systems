Overview

Target: three drag_data_source Flask containers (ports 8001–8003) and, transitively, drag_llm_service (port 9000), which fans out every query to all three sources before generating an answer.

Two implementations were run against real infrastructure: a calibrated wave-based congestion simulation (deterministic, seeded, no Docker needed) and a genuine concurrent HTTP flood against the live containers, scored with 13 real NLG metrics against PubMedQA ground truth. Full technical writeup: reports/ddos_attack.md.

🐛 Bug found and fixed this session

A response-parsing bug silently deflated every text-overlap metric, not just exact_match.

Root cause

drag_llm_service/src/models/open_model.py stripped the Llama-3 chat-template header markers and the literal word "assistant", but not a leaked "system"/"user" role token that occasionally prefixed the raw generation — e.g. the model's real output was the literal string "system\nyes", not "yes".

Fix applied

Added _strip_leaked_role_tokens() to open_model.py, pushed live into the running container, and confirmed with a direct test query returning a clean "yes". All numbers on this page use the corrected text.

Key findings

  • Zero redundancy margin. drag_llm_service waits up to 10s per source; with only 3 sources, losing any 1–2 is graceful degradation, but losing all 3 simultaneously is a hard, near-total outage — confirmed again live this session (80% failure, matches the original 85% finding within run-to-run noise).
  • Silent degradation is the dangerous regime. At low/mid severity, every query still returns 200 OK while answer quality has already measurably collapsed — invisible to status-code-only monitoring.
  • No admission control. Flask-Limiter's flat 60/min-per-IP cap is real and fires (confirmed: >96% of flood requests got 429), but it doesn't prevent the outage — the single-threaded Flask dev server queueing does the actual damage once all three sources are contended.
Recommendations (from reports/ddos_attack.md §14)

High priority: production WSGI server (gunicorn/waitress) for the data-source Flask apps; load-aware routing in drag_llm_service so it skips a source that's already timed out instead of always waiting the full 10s.
