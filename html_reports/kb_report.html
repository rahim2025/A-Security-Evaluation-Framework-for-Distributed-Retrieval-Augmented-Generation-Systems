Overview

Target: the three drag_data_source /query retrieval endpoints (ports 8001–8003), and drag_llm_service for indirect (generation-mediated) leakage.

An attacker holding the system's single, shared, hardcoded API key sends a modest, topic-balanced probe set and reconstructs a large fraction of each source's private document collection — with zero noise, since raw retrieval either returns a genuine corpus passage or nothing. Full technical writeup: reports/kb.md.

Defense results — QueryDiversityThrottle

Read this before the numbers

This defense was measured against source_1, whose ground truth has only 10 distinct topics total, against a threshold (max_topics_per_window=5) set at half that count. A topic-balanced attacker was always going to trip it almost immediately on this specific corpus. This demonstrates the mechanism works — it is not yet evidence of the block rate to expect at realistic topic scale.

🐛 Bug found and fixed this session

Rate-limit confound, silently indistinguishable from a real result

A re-run of the defense comparison on 2026-07-13 came back with docs_extracted=0 in both the undefended and defended phases — not a real result. Root cause: the DDoS live-flood test had just sent >150K requests to the same shared 60-req/min-per-IP Flask-Limiter budget, and probe_source() silently coerced every resulting HTTP 429 into a generic error, indistinguishable in the log from "the attack genuinely found nothing." Confirmed by direct curl test: the source was healthy and returning 200 moments later.

Fix applied

attack/kb_extraction/run_attack.py's probe_source() now tracks rate_limited_count separately from other errors, retries once respecting Retry-After, and defense/kb_extraction_defense/run_defense.py prints an explicit warning if any probe was rate-limited — mirroring the fix the sibling SFA module already had (§12.9 of its report).

Key findings

  • Extraction accuracy is always 1.0. Raw retrieval either returns a genuine corpus passage or nothing — there is no hallucination/noise channel at this layer, so a defender can't rely on "junk dilutes the haul" as incidental protection.
  • Topic-balanced sampling is empirically validated. topic_coverage=1.0 on source_1 with only 54 probes confirms the stratified-sampling theory (§2.3 of the report).
  • Confidentiality currently rests entirely on one fixed, shared API key — reliable-derag-secret-2026, hardcoded in docker-compose.yml, never rotated.
Recommendations (from reports/kb.md §14)

High priority: rotate the shared API key to per-client, revocable credentials; deploy QueryDiversityThrottle as a real before_request hook, not just an offline evaluation script. Medium: recalibrate the throttle's thresholds against this deployment's real topic count before citing 82.5% as production-representative.
