1. Executive Summary

Two runs of the MIA attack were executed: a dry-run (random scores, no LLM) and a live Docker run (real all-MiniLM-L6-v2 embeddings, real sources_0.jsonl passages). Both runs returned AUC-ROC ≈ 0.50 — the threshold for "no privacy signal".

The dry-run result (0.4432) is the expected random baseline and confirms the code pipeline is correct. The live run result (0.5000) is also effectively random, but for a different and important reason: the LLM service at localhost:9000 was not reachable from inside the Docker sfa container, so every probe returned an empty response and every cosine similarity was forced to 0.0000. With all scores identical, the classifier cannot separate members from non-members.

Current privacy verdict: NEGLIGIBLE — but this reflects a networking limitation, not a genuine finding. The attack must be re-run either from the host (outside Docker) or with the Docker network configured to reach the LLM service.

4. Root Cause Analysis — Why All Similarities = 0.0000

Root cause: The sfa Docker container runs with its own network namespace. When the attack script calls localhost:9000, it resolves to the container's own loopback interface — not the host machine where the LLM Flask service is listening. Every HTTP request times out silently, _query_llm() returns "", and the code correctly falls back to sim = 0.0. 
# What happens inside the sfa container:
# request -> localhost:9000 -> container's OWN loopback -> ECONNREFUSED
# _query_llm() catches exception, returns ""
# sim = 0.0 (both member and non-member)
# All 50 scores identical -> threshold = 0.0 -> all predicted member
# AUC-ROC = 0.50 (degenerate, not a real result)
Per-probe evidence: Every single one of the 50 probes (25 member + 25 non-member) shows sim=0.0000. This uniform pattern is impossible with a functioning LLM — it is definitive proof that all 50 HTTP requests failed silently, not that the RAG system has no privacy leakage.

7. How to Fix & Re-run the Live Attack

Option A — Run from host (recommended, simplest)

Running directly on the host bypasses the Docker network issue entirely. The host's localhost:9000 reaches the LLM service correctly. 
# Ensure Docker services are up
docker compose up -d

# Run MIA from host Python (not inside Docker)
python3 attack/mia/run_attack.py --seed 42
python3 attack/mia/run_attack.py --seed 0
python3 attack/mia/run_attack.py --seed 1
python3 attack/mia/run_attack.py --seed 2

Option B — Add host networking to docker-compose.override.yml

services:
  sfa:
    image: python:3.10-slim
    working_dir: /app
    volumes:
      - .:/app
    network_mode: host          # ← ADD THIS LINE
    environment:
      - HF_TOKEN=${HF_TOKEN:-}
      - HUGGINGFACE_HUB_TOKEN=${HUGGINGFACE_HUB_TOKEN:-}
    command: ["python3", "--version"]
# Then run as before
docker compose run --rm sfa bash -c \
  "pip install sentence-transformers scikit-learn numpy requests -q && \
   python3 attack/mia/run_attack.py --seed 42"

Option C — Override the LLM URL to the host IP

# Find host IP from inside Docker (usually 172.17.0.1 on Linux)
docker run --rm python:3.10-slim bash -c "ip route | awk '/default/{print \$3}'"

# Then pass it explicitly
docker compose run --rm sfa bash -c \
  "pip install sentence-transformers scikit-learn numpy requests -q && \
   python3 attack/mia/run_attack.py --llm_url http://172.17.0.1:9000 --seed 42"

8. Expected Results Once LLM Is Reachable

Based on the knowledge base content (Notre Dame passages from sources_0.jsonl) and the non-member set (perturbed versions from sources_100), the expected live AUC-ROC range depends on how verbatim the LLM's retrieval-augmented responses are:

ScenarioExpected AUC-ROCExplanation
LLM directly quotes KB text0.75 – 0.90HIGH risk — response paraphrases member passage closely; non-members get generic or unrelated response
LLM paraphrases moderately0.60 – 0.75MEDIUM risk — some signal but diluted by generative paraphrasing
LLM generates freely (no retrieval signal)0.50 – 0.60LOW/NEGLIGIBLE — RAG diversity or LLM temperature suppresses membership signal

The non-member passages are not truly "out-of-distribution" — they are lightly perturbed versions of the same KB text (changed dates, years). This means the attack may show a lower AUC than if genuinely unrelated non-members were used, since the LLM retriever may also recall the perturbed non-members from the same topic domain.
